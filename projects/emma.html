Emma: A robot girl that likes to talk

▶ Watch the demo

Overview

Emma is a social robot designed to interact with children in a natural and engaging way. Her soft, colorful appearance is intended to feel friendly and approachable. Cameras, microphones, and touch sensors give her the inputs needed to perceive her surroundings and respond during an interaction.

I spent approximately two months on the project, from CAD design through assembly and testing. I designed the robot in Fusion 360 and cast its soft face in tinted silicone using a 3D-printed mold. The remaining structure combines 3D-printed parts with off-the-shelf components. A Raspberry Pi 3B+ runs the Python software and uses its GPIO interface to read sensors, manage the displays, and control the servos.

The result is a working social-robot platform that can support natural interactions with children. It is also a foundation for continued research, with room for additional behaviors, improved sensing, and further mechanical refinement.

The rest of the robot uses 3D-printed parts coated with transparent resin for protection, particularly around the painted surfaces. The parts are designed to be assembled and disassembled easily, making future changes and maintenance more practical.

The electronics are organized around the Raspberry Pi. Because many components connect to the controller, I designed a custom circuit board to provide cleaner wiring and easier troubleshooting. Fusion 360 allowed me to develop the mechanical CAD and PCB in the same workflow, improving the fit between the electronic and mechanical parts.

Software

Emma's software is organized into parallel components so new behaviors can be added without rewriting the entire system. Separate threads handle face tracking, conversation management (TTS, STT, and LLM logic), self-monitoring of sensors and APIs, and the physical interface button. This separation is intended to isolate failures and keep unrelated functions available when one component encounters an error. In a production system, this behavior would also require explicit exception handling or process supervision.

At each boot, a self-monitoring routine checks the connected components and APIs. The status is shown on the LCD and on the rear display before interaction begins. If a dependency is unavailable, the system can alert the user instead of starting with an incomplete configuration.

The Raspberry Pi cannot run every model locally, so heavier processing is exposed through APIs on more capable machines. My main computer runs the LLM through LM Studio, while a Docker development container handles speech-to-text with a lightweight Whisper setup and text-to-speech through the Kokoro container.

This division leaves the Raspberry Pi responsible for hardware control and basic interaction logic while offloading model inference and speech processing. The resulting responsiveness depends on network latency and the availability of those external services.

Results

Emma combines a soft physical interface, custom electronics, and modular software to support more natural interaction. The capacitive touch sensor is functional but is not currently used because the long wires introduce too much noise. The current prototype works as a research platform, while future work can improve sensing reliability, autonomy, and the enclosure.
