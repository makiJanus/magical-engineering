Universal Remote Controller

▶ Watch it on my YouTube channel!

The problem

Most universal remotes solve compatibility by adding more buttons. The result is often a crowded interface with many controls that are rarely used. I wanted to explore the opposite approach: a remote that presents only the controls needed for the selected device or mode. This first iteration was built with components already available to me. The goal was not to create a final commercial product, but to test whether a smaller, context-aware interface could remain practical in everyday use.

Design direction

The design moves away from the traditional bar-shaped remote. Off-the-shelf modules make the prototype larger than a custom production board, but they also make the system easier to assemble, modify, and debug. This version therefore prioritizes a functional proof of concept and fast iteration over miniaturization.

Physical controls

The main navigation control is an AS5600 magnetic Hall-effect sensor. Instead of using a mechanical encoder, the sensor measures the angle of a magnet with 12-bit resolution and reports it over I2C. The firmware compares the angle between successive readings and converts that change into the same directional steps normally produced by encoder pulses. This provides smooth menu navigation without relying on mechanical encoder contacts.

The physical interface also includes six buttons. Each button has its own RC filter to reduce contact bounce and make presses more reliable. Two buttons have fixed functions, OK and Return/Back. The other four are context-sensitive and change their function according to the selected screen or mode.

The interaction model has two steps: select a registered device, then rotate through its available functions and choose the command to send. The remote replaces a large fixed button array with a smaller set of controls whose meaning changes with the current screen.

Each context-sensitive button always corresponds to the same screen position: A is upper left, B is lower left, C is upper right, and D is lower right. Keeping these positions consistent supports muscle memory and makes the remote easier to operate without looking down.

A device can be registered in two ways. Its commands can be defined directly in the source code, or the remote can learn them from an existing controller. In learning mode, it listens for incoming IR codes and stores them in permanent memory, making it possible to add devices without changing the firmware.

The interface is displayed on a 1.28-inch TFT LCD driven by the GCA9A01 controller. The LVGL graphics library handles the screens, menus, and visual states so the display can reflect the currently selected device and command.

Electronics and assembly

An ESP32 coordinates the user interface, sensor, buttons, IR communication, and display. A custom PCB brings these elements together and includes a driver for the haptic feedback motor, along with connectors for the display, buttons, and sensor array.

The completed prototype houses the electronics in a custom 3D-printed enclosure. This final assembly is where the electrical and mechanical decisions can be evaluated together, including component placement, clearances, and access to the controls.

Conclusion and next steps

This first iteration validates the core idea: a context-aware interface can reduce button clutter while retaining the functions needed for several devices. The remote is also rechargeable, using the custom 3.3 V charging circuit described in a previous project: 3.3V Charger Circuit.

The mechanical and electronic designs were developed in Fusion 360. Keeping the CAD and circuit work in one workflow made it possible to model the populated PCB in three dimensions, verify component clearances, and refine the enclosure before assembly.

The next version will investigate replacing the physical buttons with a touch screen. It will also incorporate feedback from this prototype and evaluate a new development board, with the aim of improving the interaction model without losing the simplicity of the first version.
